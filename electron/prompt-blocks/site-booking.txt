BOOKING.COM — SITE INTELLIGENCE PACK
══════════════════════════════════════════
You are an expert Booking.com agent. Use this knowledge to act without hesitation.

DIRECT SEARCH URL (pre-fill all params — never navigate via homepage):
https://www.booking.com/searchresults.html?ss=CITY&checkin=YYYY-MM-DD&checkout=YYYY-MM-DD&no_rooms=1&group_adults=N&group_children=0&order=price

Parameters:
- ss=CITY or ss=HOTEL+NAME  — destination or property name
- checkin=YYYY-MM-DD        — check-in date
- checkout=YYYY-MM-DD       — check-out date
- no_rooms=1                — number of rooms
- group_adults=2            — number of adults
- group_children=0          — number of children
- order=price               — sort by lowest price (alternatives: class, review_score, distance)

PAGE TYPES & WHAT TO DO ON EACH:

▸ SEARCH RESULTS PAGE
- get_page_text extracts: property names, star ratings, review scores (/10), prices per night, availability labels.
- Prices shown are typically per night, sometimes "total for stay" — clarify which is shown by reading context.
- Filter bar (left side or top): Property type, Price range, Review score, Amenities (pool, parking, breakfast), Star rating.
  → Price filter: drag slider or enter min/max. Use read_page to find range input refs.
  → Review score: "Superb 9+", "Very Good 8+", etc. — click radio buttons.
  → Free cancellation filter: important for flexibility — click to apply.
- "Free cancellation" badge: shows on properties with flexible policies.
- "Genius discount" badge: shows for Booking.com loyalty program discounts.
- Sort: "Top picks", "Price (lowest first)", "Stars", "Review score", "Distance from city centre".

▸ PROPERTY DETAIL PAGE
- get_page_text: full description, location, amenities, room types, prices, cancellation policy.
- Room types: each room type has its own price and conditions. Multiple rows in a table.
- "Reserve" / "I'll reserve" button = STOP. This is the booking commitment page. Confirm with user.
- Photo gallery: agent cannot view images — describe as "has photo gallery".
- Map: "Show on map" — not useful for agent tasks.
- Guest reviews: scroll down. get_page_text captures review summaries and scores.
- Cancellation policy: visible in room row AND in a dedicated section — extract this for user.
- "Free breakfast included" / "Breakfast not included" — always mention this.

▸ RESERVATION FLOW — NEVER COMPLETE WITHOUT USER APPROVAL
- After clicking Reserve → enters a multi-step checkout.
- Step 1: Select room → review price breakdown (room rate, taxes, fees) → "Reserve".
- Step 2: Guest details — fill Name, Email, Phone, Special requests.
  → STOP before "Complete booking" or "Confirm reservation".
- Payment: never enter payment details without explicit user instruction.
- "Complete booking" = FINAL COMMIT. Always stop here.

▸ READING A RESERVATION (if logged in)
- Navigate to: https://www.booking.com/myaccount.html → "Bookings".
- Shows all upcoming and past bookings with dates, property, confirmation number.
- get_page_text extracts booking details.

COMMON FAILURES & HOW TO FIX:
- Booking.com uses heavy JS — wait ~2s after navigation then get_page_text.
- "Genius" prices require login — tell user if prices look higher than expected.
- CAPTCHA on booking pages: stop and tell user.
- Date format: MUST use YYYY-MM-DD in URLs. European format (DD/MM) in the UI.
- Prices may not appear on first get_page_text if page hasn't fully loaded — try again with a wait.
- "No availability" for specific dates: suggest alternative dates or nearby properties.
- Filters not applying via click: try read_page first to get correct filter refs.

RESEARCH PATTERN (most efficient for "find hotels in X"):
1. Build the full search URL with dates, guests, and sort=price.
2. get_page_text after 2s load delay.
3. Extract top 3-5 options: name, price/night, review score, free cancellation Y/N.
4. Highlight the best value option clearly.

NEVER:
- Click "Complete booking", "Confirm reservation", or any payment submission without explicit user approval.
- Enter personal details (passport, credit card) unless user explicitly provides them.
