DIRECT URLS — jump straight, never navigate through homepage:
- Repo home:        https://github.com/OWNER/REPO
- File:             https://github.com/OWNER/REPO/blob/BRANCH/PATH/TO/FILE
- Raw file:         https://raw.githubusercontent.com/OWNER/REPO/BRANCH/PATH/TO/FILE
- Issues list:      https://github.com/OWNER/REPO/issues
- Single issue:     https://github.com/OWNER/REPO/issues/NUMBER
- PRs list:         https://github.com/OWNER/REPO/pulls
- Single PR:        https://github.com/OWNER/REPO/pull/NUMBER
- PR diff:          https://github.com/OWNER/REPO/pull/NUMBER/files
- Actions:          https://github.com/OWNER/REPO/actions
- Releases:         https://github.com/OWNER/REPO/releases

PAGE TYPES & WHAT TO DO ON EACH:

▸ REPOSITORY HOME PAGE
- README is rendered below the file tree — get_page_text captures it.
- File tree: list of directories and files with sizes and last-commit messages.
- "Code" green button → Clone URL (HTTPS, SSH, GitHub CLI). read_page to find it.
- Stars, forks, watchers: visible at the top right next to the repo name.
- Main branch name: shown in the branch dropdown (default: main or master).
- Description + topics: in the sidebar on the right.

▸ FILE BROWSER
- Navigate directly to file URL (blob/BRANCH/PATH) — fastest approach.
- File content is rendered in a code block. get_page_text extracts raw code cleanly.
- For large files, navigate to RAW URL (raw.githubusercontent.com) for full plain-text.
- "Edit" (pencil icon): only if user has write access. Opens in-browser editor.
- Download: "Raw" button gives direct file URL — navigate to it for plain text.

▸ ISSUES
- List: get_page_text extracts issue titles, numbers, labels, authors, dates.
- Filter by: label, assignee, milestone, author — URL params: ?labels=bug&assignee=user
- Open an issue: navigate to /issues/NUMBER.
- Issue body + all comments: get_page_text gives the full thread in one call.
- Create issue: navigate to /issues/new. Fill Title (type_text) and body (insert_text in textarea). "Submit new issue" is the final commit — confirm with user.
- Close issue: "Close issue" button at the bottom of the issue page.
- Labels: click "Labels" in the right sidebar to add/remove.

▸ PULL REQUESTS
- PR list: same pattern as issues. get_page_text for quick scan.
- PR detail page: shows description, review status, checks (CI), comments, merge status.
- PR diff (/pull/NUMBER/files): shows all file changes. Each file is collapsible. get_page_text gives the full diff as text (slower but complete). For large diffs, navigate to individual file tabs.
- Checks/CI status: bottom of PR page. Green checkmark = pass, red X = fail. Click the check name to see build logs.
- Review: "Add your review" button. Leave inline comments by clicking the "+" icon on diff lines.
- Merge: "Merge pull request" button — FINAL COMMIT. Never click without explicit user approval. Options: Merge, Squash, Rebase.
- Resolve conflicts: GitHub shows a conflict resolver in-browser. Or guide user to do it locally.

▸ CODE SEARCH
- Global search: use https://github.com/search?q=QUERY+language:javascript&type=code
- In-repo search: use https://github.com/search?q=QUERY+repo:OWNER/REPO&type=code
- Results show file snippets. Click a result to go to the file, highlighted at the matching line.
- get_page_text on search results page extracts snippets quickly.

▸ ACTIONS / CI
- Navigate to /actions to see all workflow runs.
- Click a run to see job list and status.
- Click a job to see step-by-step logs.
- "Re-run failed jobs" button appears for failed runs — confirm with user before clicking.
- Workflow files are in .github/workflows/ — navigate there to see YAML configs.

▸ RELEASES
- Navigate to /releases. Latest release is first.
- Each release: tag name, title, changelog, download assets (.zip, .exe, etc.).
- get_page_text extracts release notes and asset names.
- Direct download link: click the asset file link to get the URL.

COMMON FAILURES & HOW TO FIX:
- "Sign in" wall: stop and tell user.
- Large files: use raw.githubusercontent.com URL for reliable text extraction.
- Code view is a syntax-highlighted table — get_page_text strips HTML and gives clean code.
- Diff view uses complex table structure — get_page_text is more reliable than read_page for diffs.
- SPA navigation: after clicking links in GitHub (it uses Turbo/SPA), call read_page again before the next action.
- 404 on file path: the branch name may not be "main" — check the repo home for the default branch name.
- Private repo without login: stop and tell user authentication is needed.

GIT OPERATIONS (none via browser — give user the commands):
When user asks to clone, commit, push, or run git commands:
→ Give them the exact git command to run in their terminal.
→ Clone: git clone https://github.com/OWNER/REPO.git
→ Never try to simulate git via browser tools.

NEVER:
- Click "Merge pull request" without explicit user approval.
- Click "Delete branch" without explicit user approval.
- Submit a new issue or PR without explicit user approval.
- Click "Confirm" on any destructive action (delete repo, close milestone, etc.).
