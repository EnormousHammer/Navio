PAGE TYPES & WHAT TO DO ON EACH:

▸ BOARD (SCRUM/KANBAN)
- get_page_text: column names (To Do, In Progress, Done), issue cards with keys and summaries.
- Cards are draggable — but agent should use the issue detail page to change status.
- Click a card (ref from read_page) to open the issue detail panel on the right or navigate to the issue.

▸ ISSUE LIST / BACKLOG
- get_page_text: issue keys, summaries, assignees, priority, status, story points.
- Filter/search: "Filter issues" input at top. Type to filter by text.
- Sort: click column headers.

▸ SINGLE ISSUE PAGE (PROJ-123)
- get_page_text: summary, description, status, assignee, reporter, priority, labels, sprint, story points, comments, linked issues, attachments.
- Status transitions: click the status badge → dropdown shows available next statuses → click to transition.
  → Transitioning status = real change. Confirm with user before clicking.
- Assignee: click the assignee field → search and select person.
- Comment: scroll to bottom → comment box → insert_text → click "Save".
  → FINAL COMMIT for comments. Confirm with user.
- Edit fields (inline): most fields are clickable — click to enter edit mode → insert_text or select_option → click "Save" or press Enter.
- Subtasks: listed below the description. Click to open.
- Linked issues: shows blocking/blocked-by/related links.

▸ CREATING AN ISSUE
- Navigate to create URL or click "Create" button in the top nav.
- Fill: Project (dropdown), Issue type (Bug/Story/Task/Epic), Summary (text), Description (rich text), Assignee, Priority, Labels, Sprint.
- Description is a rich text editor (similar to Atlassian's "Fabric" editor) — use insert_text.
- "Create" button = FINAL COMMIT. Confirm with user.

COMMON FAILURES & HOW TO FIX:
- Jira is a heavy React app — always wait after navigation and re-read before acting.
- Rich text fields: use insert_text, not type_text.
- Status transition dropdown not appearing: the status badge may need a direct click — get ref from read_page.
- Issue not found: confirm the issue key format (PROJECT_KEY-NUMBER, e.g. DEV-42).
- Comment box not visible: scroll to the bottom of the issue page.
- "You don't have permission": stop and tell user they need Jira access for this project.

NEVER:
- Transition an issue status without user approval.
- Delete an issue or epic without explicit confirmation.
- Post a comment without user approval.
